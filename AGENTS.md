# AGENTS.md

## Stack

- Next.js 16 (App Router), React 19, TypeScript strict, Tailwind CSS v4
- Package manager: **pnpm**
- Scripts: `pnpm dev`, `pnpm build`, `pnpm lint` (plain `eslint`)

## Architecture: MVVM

The current app is a static replica (see below). Any new feature code goes
under `src/` and follows Model–View–ViewModel:

```
src/
  app/          # Routes only. Pages stay thin: render a View, nothing else.
  models/       # Model: types + pure domain logic. No React, no I/O.
  services/     # Data access (API/DB/mock). Async, framework-free, no React.
  viewmodels/   # ViewModel: "use client" hooks. Owns state + orchestration,
                # calls services, exposes a typed view model to the View.
  views/        # View: presentational components. Render the view model,
                # no business logic, no direct service calls.
  components/   # Shared UI primitives (add when needed).
```

Dependency direction is one-way: `views → viewmodels → services → models`.

## Rules

- Pages in `src/app` stay thin: a Server Component page may call a Service
  once for initial data (wrap async calls in `<Suspense>`), then hand it to a
  View. All client state, refetching, and interactivity live in the ViewModel.
- Views are props-driven and testable without Next.js routing.
- No data fetching in `useEffect`; fetch initial data on the server.
- Read `node_modules/next/dist/docs/` before using unfamiliar Next.js APIs.
- Tailwind v4: styling is CSS-first (`@import "tailwindcss"` +
  `@theme` in `src/app/globals.css`), no `tailwind.config.js`. Do not import
  it in the replica's root layout — see below.

## Nordstrom replica (site root `/`)

- The home page (`src/app/page.tsx` + root layout) is a 1-to-1 copy of a saved
  nordstrom.com homepage. Do not "improve", restructure, or restyle its
  markup — it must stay byte-identical to the captured DOM (bar the
  documented capture transforms below).
- Page markup: generated `src/lib/nordstrom/body.ts` (captured `<body>` inner
  HTML, with the transforms below). Styles: generated `src/lib/nordstrom/css.ts`.
  Both are regenerated by `node scripts/build-nordstrom.mjs` from the vendored
  capture (`scripts/nordstrom-capture.html`) and `src/lib/nordstrom/styles/`;
  edit those sources, never the generated blobs. CDN-hosted images referenced
  by the capture are vendored first: `node scripts/fetch-media.mjs` downloads
  every nordstrommedia url to `public/assets/media/<sha1(rawurl)>.<ext>`.
- Capture transforms (all asserted by the build script):
  - `<script>` tags stripped; everything after the footer's structural closes
    cut (tracker `<noscript>`, sierra/chat widget, beacon iframes).
  - saved-page asset refs and `/static/nordstrom/res/v4/` → `/assets/`;
    nordstrommedia urls → local `/assets/media/…`; non-image media (the 127MB
    catalog pdf) → `#`.
  - **No nordstrom-domain url may ship** in `body.ts`/`css.ts` — every
    remaining `nordstrom.com`-family url is rewritten to `#` (visible text,
    class names and css vars keep their original names).
- Captured assets live in `public/assets/` (ignored by ESLint — they are
  third-party verbatim copies). Brandon Text fonts sit at the public root.
- Copy/save protections live in `src/app/layout.tsx` (robots metadata +
  user-select/print/drag css + contextmenu/copy/keyboard guards) and
  `next.config.ts` headers (X-Robots-Tag, X-Frame-Options, nosniff,
  no-referrer). Keep them in place.
- The hero carousel is interactive by exception (user request). Do not edit
  the captured slide markup — enhancement lives in MVVM code that hooks the
  design system's own controls: `src/models/heroCarousel.ts` (pure logic),
  `src/viewmodels/useHeroCarousel.ts` (autoplay/controls wiring; moves the
  captured `.A73U5` active class between `.KPEM6` slides), and
  `src/views/HeroCarouselEnhancer.tsx` (client mount from `page.tsx`).
- The root layout has no Tailwind import; `next.config.ts` scopes Tailwind's
  transform to `src/app/globals.css` only, because Tailwind's parser corrupts
  the captured minified CSS. New non-replica routes should live in their own
  route-group root layout if they need Tailwind.
